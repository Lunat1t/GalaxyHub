# GalaxyHub: Contextual Retrieval

Работающий сервис поиска по материалам Project Rooms и клиент для интеграции с GalaxyCode. Основа — [статья OTUS](https://habr.com/ru/companies/otus/articles/1054594/) и [оригинальная техника Anthropic](https://www.anthropic.com/engineering/contextual-retrieval).

## Работа через вход в Codex

Добавлен режим `codex`: локальный Codex App Server использует сохранённый вход через ChatGPT. API-ключ OpenAI или Anthropic не требуется. Система не читает, не копирует и не возвращает токены авторизации — ими управляет Codex. Вызовы расходуют доступные лимиты аккаунта.

```sh
# Только если вход ещё не выполнен:
codex login
# Создать настройки со случайным серверным секретом (существующий .env не перезаписывается):
npm run codex:setup
# Проверить реальную индексацию, поиск и ответ через HTTP API:
npm run codex:check
# Загрузить концепцию GalaxyHub в постоянную базу и проверить ответ:
npm run codex:seed
# Запустить постоянный сервис:
npm start
```

После запуска открой `http://127.0.0.1:8787/`: стартовая страница объясняет, как пользоваться сервисом. Это пока API, а не браузерный чат. Для вопроса открой второй терминал в папке GalaxyHub:

```sh
npm run ask -- "Как включается голосовой чат в Café?"
```

Команда автоматически использует секрет из `.env`, не печатает его и возвращает ответ с источниками. По умолчанию используется комната `cafe`; другую можно задать через `GALAXY_ROOM`. Если открыть защищённый `/v1/` адрес напрямую в браузере, сообщение `Valid bearer token required` означает отсутствие ключа в запросе, а не проблему входа в Codex.

`codex:setup` выбирает `gpt-6-astra`; при необходимости укажите другую доступную модель в `CODEX_MODEL`. Эта настройка относится только к сервису GalaxyHub и не меняет пользовательские настройки Codex. Модель фиксируется в профиле базы; при смене модели нужно создать новую базу и переиндексировать документы. Если не указать `CODEX_MODEL`, адаптер использует модель из настроек локального Codex. Каталог моделей не гарантирует доступ — его подтверждает успешный реальный запрос.

В этом режиме Codex создаёт контекстные пояснения и формирует ответ. Поиск выполняется локально через BM25 по обогащённым фрагментам. Embeddings API через браузерный вход не подключён: `dense` и `hybrid` в режиме Codex отклоняются, чтобы не выдавать поиск по словам за семантический. Remote-режим с embeddings остаётся доступным отдельно.

Для каждого пояснения или ответа создаётся новая временная беседа без общей истории между комнатами. Codex запускается в пустой временной папке с режимом чтения, отключёнными shell, MCP, плагинами, поиском в интернете и делегированием. Адаптер не выполняет запросы интерактивных инструментов и останавливает генерацию при попытке использования инструментов. Пользовательская конфигурация Codex не изменяется. Системные ограничения администратора сохраняются; несовместимые версии CLI могут потребовать обновления адаптера.

Новый endpoint `POST /v1/answer` принимает те же поля, что и `/v1/search`, и возвращает `answer`, `citationIds`, `context`, `diagnostics`. Сервер проверяет доступ до поиска и обращения к Codex, затем проверяет, что ссылки ответа существуют среди переданных источников. Это проверка ссылок, а не автоматическое доказательство правильности каждой фразы. При отсутствии подходящих материалов он сообщает об этом без вызова модели.

```ts
const result = await knowledge.answer({
  room: 'cafe', query: 'Как включается голосовой чат в Café?'
});
console.log(result.answer);
console.log(result.context.passages);
```

`codex:check` использует временную базу и локальный HTTP-сервер, загружает `Galaxy-Hub.md`, получает ответ с цитатой и сохраняет проверку в `reports/codex-check.json`. Модель вызывается дважды: для контекста и для ответа. После проверки сервер и App Server закрываются. Команда не наполняет постоянную базу; материалы для рабочего сервиса нужно загрузить через клиент или API.

`codex:seed` выполняет тот же путь с постоянной базой из `.env` и настроенным размером фрагмента. После этой команды рабочий сервис содержит концепцию GalaxyHub в комнате `cafe`. Повторный запуск не пересчитывает неизменённый документ, но проверка ответа снова вызывает Codex.

Подключение локального Codex через App Server описано в [официальной документации](https://learn.chatgpt.com/docs/app-server). Этот режим предназначен для локальной доверенной установки. Он не реализует публичную кнопку входа каждого пользователя GalaxyHub и не является общим сервером для расходования одного личного аккаунта всеми посетителями.

В исходной папке была только концепция `Galaxy-Hub.md`: веб-приложения, аккаунтов и репозитория GalaxyCode здесь нет. Поэтому система реализована отдельным модулем с HTTP API. Его можно подключить к будущему серверу Next.js и GalaxyCode, не привязывая поиск к игровому миру.

## Поиск прямо из Codex через MCP

Сервер `galaxyhub_knowledge` подключён к локальной конфигурации Codex. Он предоставляет три инструмента: `list_rooms`, `list_documents`, `search_knowledge`. Codex получает найденные фрагменты и сам составляет ответ в текущем чате. Вложенного запуска Codex или дополнительных запросов к моделям при поиске нет.

Пример сообщения в чате проекта: «Найди в материалах GalaxyHub, как устроены комнаты проектов, и укажи источники». `AGENTS.md` содержит инструкцию использовать поиск для таких вопросов и отличать планы из концепции от уже реализованных функций.

MCP запускается Codex автоматически как локальный процесс. Он читает существующую SQLite-базу в режиме read-only, поэтому `npm start` для этого подключения не нужен. `.env` задаёт базу и границы доступа; если настроен один серверный ключ, используется его организация и список комнат. При нескольких ключах выберите один через `GALAXY_MCP_TOKEN`. Сами ключи не возвращаются инструментами и не копируются в конфигурацию Codex. MCP не индексирует документы и не удаляет их.

Проверки:

```sh
npm run mcp:check
npm run mcp:codex-check
```

Первая проверяет MCP-протокол и реальные фрагменты, вторая проверяет обнаружение инструмента и вызов поиска через Codex App Server. Обе не вызывают генерацию модели. Результаты сохраняются в `reports/mcp-check.json` и `reports/codex-mcp-check.json`.

Для повторного подключения на этой машине:

```sh
codex mcp add galaxyhub_knowledge -- /usr/bin/node --env-file=/home/bah/GalaxyHub/.env /home/bah/GalaxyHub/src/mcp.mjs
```

Для другой машины замените абсолютные пути и проверьте наличие Node.js 22.13+. Не регистрируйте команду `npm run mcp` как транспорт: npm пишет служебные сообщения в stdout, а MCP требует только сообщения протокола. Обычный `npm run mcp` подходит лишь для ручного запуска.

Уже открытая сессия может не получить новый набор инструментов автоматически. Откройте новую сессию проекта или перезапустите локальное приложение, если инструмент не появляется. До обновления инструментов Codex может использовать ту же базу через `npm run search -- "вопрос"`; это локальный поиск без модели и без HTTP-сервера.

## Запуск

Требуется Node.js 22.13+ с `node:sqlite`. Внешних зависимостей нет. SQLite в Node 22 может печатать уведомление об экспериментальном API.

```sh
npm test
npm run demo
npm run evaluate
cp .env.example .env
# Задайте случайный секрет в GALAXY_TOKENS, затем:
npm start
```

`demo` запускает временный локальный API, индексирует реальную концепцию GalaxyHub и извлекает материалы через клиент GalaxyCode. После завершения сервер закрывается. `start` сохраняет индекс в `data/retrieval.sqlite` между запусками.

Режим `demo` использует контекст из метаданных и хешированные частоты слов: это проверка всей системы без ключей и сетевых запросов, не семантическая модель. Режим отражается в диагностике каждого поиска. Для настоящих LLM-контекстов и семантического поиска используйте `remote`.

## Как работает

1. Сервер проверяет токен, организацию, комнату и право записи.
2. Текст делится на фрагменты с перекрытием; сохраняются исходное форматирование, смещения и номера строк. Размер задаётся в словах, не в токенах модели.
3. В remote-режиме Claude получает весь документ и текущий фрагмент, генерирует короткий контекст. Общая часть запроса имеет `cache_control: ephemeral`; фактическое применение кеша зависит от минимального размера для выбранной модели.
4. Контекст добавляется к фрагменту для embeddings и BM25. Оригинал хранится отдельно.
5. Поиск выбирает только материалы доступной комнаты и организации. Векторный поиск и BM25 выполняются независимо, результаты объединяются через Reciprocal Rank Fusion.
6. При настройке rerank-провайдера кандидаты переранжируются по обогащённым фрагментам.
7. Клиент получает оригинальные фрагменты с источником, версией, строками и обозначениями для цитирования. Размер контекста ограничен; если отдельный фрагмент не помещается целиком, он пропускается.

Повторная загрузка того же документа ничего не пересчитывает. Изменение текста, названия, источника или версии переиндексирует все фрагменты: контекст зависит от всего документа. Замена атомарна; при ошибке модели предыдущая версия остаётся доступной. Записи и удаления выполняются последовательно. Профиль индекса и размерность векторов защищают от смешивания несовместимых моделей.

## Подключение моделей

В `.env` задайте `GALAXY_MODE=remote`, **новый** `GALAXY_DB`, `ANTHROPIC_API_KEY`, `CONTEXT_MODEL`, `EMBEDDING_API_KEY`, `EMBEDDING_MODEL`, `EMBEDDING_URL`. Имя модели выбирается явно. Embeddings endpoint должен принимать `{model, input}` и возвращать `{data: [{embedding: number[]}]}`. Специфичные протоколы других провайдеров подключаются через адаптер в `src/providers.mjs`.

Дополнительно задайте `RERANK_API_KEY` и `RERANK_MODEL` для Cohere v2 или совместимого endpoint. HTTP разрешён только для локальных провайдеров, остальные подключения требуют HTTPS. Таймаут запроса к провайдеру — 60 секунд. Ошибки не вызывают скрытого переключения на demo.

Код не обещает цену из заголовка статьи: стоимость зависит от корпуса, модели, кеша и тарифа. Платные вызовы появляются только после явного включения remote. Документы доступной комнаты передаются настроенным внешним провайдерам.

## API

Кроме `/health`, все запросы требуют `Authorization: Bearer <token>`. POST также требует `Content-Type: application/json`.

| Метод | Путь | Данные |
|---|---|---|
| POST | `/v1/documents` | `room, id, title, source, text`, необязательно `kind, version` |
| GET | `/v1/documents?room=...` | Метаданные документов комнаты |
| DELETE | `/v1/documents?room=...&id=...` | Удаление документа и всех его фрагментов |
| POST | `/v1/search` | `room, query`, необязательно `topK, candidates, strategy, maxContextChars` |
| GET | `/health` | Статус и режим |

`strategy`: `hybrid` по умолчанию, `dense`, `bm25`. Обычно извлекается до 40 кандидатов и возвращается 5 фрагментов. `topK` ограничен 20, кандидаты — 150. Документ ограничен 200 000 символов, HTTP-запрос — 1 MiB. Ограничение параллельных запросов защищает очередь от бесконечного роста; при перегрузке API возвращает 429.

Пример данных для индексации:

```json
{
  "room": "project-demo",
  "id": "architecture",
  "title": "GalaxyHub — архитектура Project Rooms",
  "source": "galaxyhub://rooms/project-demo/documents/architecture",
  "kind": "specification",
  "version": "2026-10-09",
  "text": "Постоянные комнаты содержат участников, переписку и ссылки на код."
}
```

`GALAXY_TOKENS` содержит серверные записи `{token, tenant, rooms, role}`. `reader` может искать и читать метаданные, `writer` также индексирует и удаляет. Значения `tenant` и списка доступных комнат из тела запроса не принимаются. Одинаковый ID комнаты в разных организациях не открывает общий доступ.

## GalaxyHub и GalaxyCode

Клиент `sdk/galaxy-code.mjs` имеет декларации типов для TypeScript и использует стандартный fetch. Он предназначен для доверенного сервера или backend расширения, не для браузерного бандла с общим сервисным секретом.

```ts
import { GalaxyKnowledgeClient } from './sdk/galaxy-code.mjs';

const knowledge = new GalaxyKnowledgeClient({
  baseUrl: 'http://127.0.0.1:8787',
  token: process.env.GALAXY_KNOWLEDGE_TOKEN!
});

await knowledge.indexCode({
  room: 'project-demo', repository: 'GalaxyCode', path: 'src/search.ts',
  revision: 'commit-sha', language: 'typescript',
  text: approvedFileContents
});

const context = await knowledge.getContext({
  room: 'project-demo', query: 'Где реализован поиск?', maxContextChars: 16000
});
// Передайте context.instruction и context.passages своему AI-ассистенту.
// passages содержат оригинал, источник, ревизию и строки, а не LLM-префикс.
```

GalaxyHub должен проверять текущего пользователя и членство в комнате на своём сервере, затем выбирать соответствующие серверные credentials. Не используйте общий токен на все комнаты для пользовательского прокси без дополнительной проверки членства. Сейчас ACL задаётся конфигурацией; при выходе пользователя из комнаты соответствующие credentials нужно отозвать или обновить, перезапустив сервис.

GalaxyCode сам выбирает разрешённые файлы, исключает секреты и служебные каталоги, передаёт текущую ревизию, переиндексирует изменения и вызывает `deleteDocument` для удалённых файлов. Клиент не читает диск и не обходит репозиторий самостоятельно. Материалы каждой Project Room изолированы; общий поиск по всем комнатам пока не реализован.

## Проверки и оценка

`npm test` проверяет изоляцию организаций и комнат, роли, HTTP-авторизацию, сохранение данных, атомарность обновлений при сбое модели, удаление, пересчёт контекста, форматирование кода, объединение результатов, reranking и лимиты.

`npm run evaluate` сравнивает обычный dense-поиск по оригиналам с contextual hybrid, показывает Recall@5, MRR@5 и NDCG@5 на небольшой размеченной выборке. Метрики считаются по уникальным документам среди первых пяти фрагментов, поэтому несколько чанков одного документа занимают часть лимита. Baseline не использует reranking. Для своего набора: `npm run evaluate -- /absolute/path/dataset.json`. Формат — как в `test/fixtures/evaluation.json`.

Remote-оценка: `node --env-file=.env scripts/evaluate.mjs /path/dataset.json`. Она вызывает платные модели; оба индекса создаются только в памяти. Маленькая демонстрационная выборка не доказывает улучшение качества: перед выпуском нужна оценка на 100–200 вопросах ваших пользователей.

## Границы текущей версии

Это рабочая первая версия сервиса извлечения контекста. В режиме Codex добавлена генерация ответа с источниками. Пользовательский интерфейс, SSO и модель членства комнат ещё не существуют в исходном проекте. Remote-адаптеры требуют проверки с действительными credentials.

SQLite хранит оригинальные документы, префиксы и векторы. Для небольшого корпуса поиск вычисляется в процессе; все доступные чанки комнаты загружаются в память. Для большого корпуса следующий шаг — PostgreSQL/pgvector, отдельный индекс BM25, очередь фоновой индексации, пакетные вызовы моделей и метрики в системе наблюдения. Anthropic Batch API в этой версии не реализован. Продолжительная индексация выполняется синхронно, поэтому для больших документов нужен job API.

Сервис слушает localhost по умолчанию. Для развёртывания потребуется HTTPS reverse proxy и интеграция с авторизацией Hub; секреты остаются на сервере. При смене модели создайте новый индекс, загрузите весь корпус, оцените качество и переключите потребителей на новый сервис.
