# Galaxy Hub

Основа первой версии: Next.js + TypeScript, Phaser, Colyseus и PostgreSQL.

## Первый запуск

Нужны Node.js 22.19 или новее и Docker с Docker Compose.

```sh
npm ci
cp .env.example .env
npm run db:up
npm run db:migrate
npm run dev
```

Сайт: http://localhost:3000. Сервер мира: ws://localhost:2567.
`dev` запускает оба сервера и завершает их вместе по Ctrl+C.
PostgreSQL работает отдельно и хранит данные в постоянном Docker volume.
Пароль из примера предназначен для локальной разработки.

## Проверка

В другом терминале:

```sh
npm run typecheck
npm run build
npm run check:services
```

`GET /api/health` проверяет PostgreSQL и сервер мира. При недоступном сервисе
возвращает HTTP 503. `check:services` также входит в пустую комнату Colyseus
и выходит из неё.

## Команды

- `npm run dev:web` — только веб-приложение.
- `npm run dev:world` — сервер мира с перезапуском при изменениях.
- `npm run world` — сервер мира без наблюдения за файлами.
- `npm run db:down` — остановить PostgreSQL, сохранив данные.
- `npm run db:migrate` — подготовить реестр миграций; повторный запуск безопасен.
- `npm run build && npm start` — сборка и запуск веб-приложения; база и мир запускаются отдельно.

Настройки находятся в `.env`, исключённом из Git. Next.js и сервер мира читают
его при запуске. `WORLD_SERVER_URL` используется сервером сайта,
`NEXT_PUBLIC_WORLD_URL` — адрес для будущего браузерного клиента.

## Структура

- `src/app` — страницы и HTTP API.
- `src/lib` — настройки и подключение к PostgreSQL.
- `src/world` — Colyseus и пустая комната `lobby`.
- `scripts` — подготовка базы и проверка сервисов.

Регистрация, аватары, чат и комнаты проектов добавляются на следующих этапах.

## Авторизация через Supabase

Главная страница использует Supabase Auth: регистрация с email и паролем,
подтверждение email, вход, выход, повторная отправка подтверждения и
восстановление пароля. Профили хранятся в таблице `public.profiles`.

1. Добавьте в `.env` `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
   из Project Settings → API. Также поддерживается старый `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
2. Выполните `supabase/migrations/202610100001_profiles.sql` один раз в SQL Editor
   нужного проекта. Миграция создаёт таблицу, автоматическое создание профиля при
   регистрации и правила доступа. При существующей таблице сначала проверьте схему.
3. В Authentication → Providers включите Email и подтверждение email.
   Минимальную длину пароля задайте не меньше 8 символов.
4. В Authentication → URL Configuration задайте Site URL адресом сайта и добавьте
   Redirect URLs: `http://localhost:3000/auth/callback` и
   `http://localhost:3000/auth/callback?next=/reset-password`.
   Для внешнего preview или публикации замените localhost фактическим origin.
5. Перезапустите приложение после изменения `.env`. Для production пересоберите его.

Браузер использует только публичный ключ. `service_role` и другие секретные ключи
не нужны приложению и не должны попадать в `NEXT_PUBLIC_*`.
Email и пароли обрабатывает Supabase Auth; в таблице профилей email не хранится.
Пользователь читает собственный профиль даже когда он скрыт, а также видимые
профили других участников. Редактировать можно только собственный профиль.
Анонимное чтение запрещено. В списке показаны до 100 видимых профилей.

Для писем с PKCE ссылка должна открываться в браузере, из которого отправлен запрос.
Если нужен переход с другого устройства, используйте шаблоны Supabase со ссылками
на `{{ .SiteURL }}/auth/callback?token_hash={{ .TokenHash }}&type=email` для
подтверждения и `{{ .SiteURL }}/auth/callback?token_hash={{ .TokenHash }}&type=recovery`
для восстановления. Оба варианта обрабатываются callback-маршрутом.

Прежние локальные аккаунты макета не переносятся автоматически. Зарегистрируйтесь
через Supabase. Локальная PostgreSQL и сервер мира продолжают запускаться отдельно;
`/api/health` проверяет их, но не состояние Supabase Auth.

Для проверки: создайте аккаунт, подтвердите письмо, войдите, измените профиль,
перезагрузите страницу, проверьте скрытый профиль из второго аккаунта,
выйдите и восстановите пароль. SQL-проверки доступа должны проверять скрытые
профили и запрет изменения чужих данных независимо от интерфейса.

В управляемом окружении Codex разрешите домен вашего проекта Supabase в настройках
сети. Серверные запросы используют унаследованный HTTP/HTTPS proxy, если он задан.
Ответ прокси 403 означает сетевой запрет; исправляется настройками окружения.

Для публикации задайте `SITE_URL` каноническим адресом сайта для callback-переходов.

## Café — третья часть первой версии

Откройте http://localhost:3000/cafe и введите гостевое имя. На карте видны только
реально подключённые участники. Для проверки присутствия откройте вторую вкладку
или другой браузер и войдите под другим именем.

Управление: стрелки / WASD, нажатие на свободную точку карты, либо удержание
кнопок направления на телефоне. Нажатие ведёт по прямой; для обхода столов
выберите следующую свободную точку. Кнопка «Чат» открывает общий канал комнаты.
Возле каждого из трёх столов появляется отдельный канал разговора.

Phaser загружается только на странице Café: при фокусе гостевой формы или кнопки
входа начинается предзагрузка, а запуск игры происходит после входа. Colyseus синхронизирует
аватары, сервер рассчитывает движение, ограничивает скорость и столкновения.
Гости выбирают имя и цвет для текущего посещения. Вход с аккаунтом использует
сохранённый профиль Supabase. Имя гостя не подтверждает
личность. Комната вмещает до 20 участников; при заполнении создаётся следующая.

Адрес сервера мира для браузера задаётся в `NEXT_PUBLIC_WORLD_URL`. При доступе
с другого устройства localhost должен быть заменён на доступный адрес сервера;
для HTTPS-сайта нужен адрес WSS. После изменения пересоберите или перезапустите сайт.

`npm run check:cafe` проверяет присутствие двух клиентов, синхронизацию движения,
ограничение скорости, остановку устаревшего ввода, границы карты и выход участника.

## Аккаунт и персонаж Café

После входа в аккаунт на странице `/cafe` появляется кнопка «Войти с профилем».
Сервер мира проверяет access token через Supabase Auth и читает собственный профиль
с RLS от имени пользователя. Имя, аватар и цвет берутся из сохранённых данных;
переданные клиентом имя и признаки аккаунта не могут подменить профиль. ID аккаунта
и токены не передаются другим участникам. В карте, списке и чате различаются аккаунты
и гости. Цвет персонажа соответствует выбранному аватару профиля.

Для скрытого профиля сервер публикует нейтральное имя и персонажа; присутствие на
карте остаётся видимым. Сообщения сохраняют имя, действовавшее при отправке.
Изменение профиля в другой вкладке обновляет персонажа после серверной проверки.
Обновления токена поддерживают длительное посещение; истёкшая сессия закрывает
подключение с аккаунтом. Выход из аккаунта закрывает посещение с профилем.

Миграция `profiles` применена через MCP к проекту `ebpsktdcrynmcuxqjvse` 11 октября
2026 года. Для опубликованного сайта добавьте в Supabase Authentication → URL
Configuration Site URL `https://galaxy-hub-irc2.onrender.com` и Redirect URLs:

- `https://galaxy-hub-irc2.onrender.com/auth/callback`
- `https://galaxy-hub-irc2.onrender.com/auth/callback?next=/reset-password`

Предзагрузка сокращает ожидание ресурсов при входе, но не устраняет холодный запуск
бесплатного Render. PWA, кеширование для повторных запусков и бесшовная смена карт
пока не реализованы.

## Чат Café — четвёртая часть первой версии

Общий чат доступен всем гостям текущей комнаты. Чтобы открыть разговор у стола,
подойдите к его кругу на карте и выберите появившуюся вкладку. Доступ к отправке,
доставке и истории стола определяется положением персонажа на сервере. При уходе
от стола его переписка удаляется из открытой панели. Имя автора берётся из гостевого
персонажа, а не из отправленного сообщения.

Enter отправляет сообщение; Shift+Enter добавляет строку. Во время набора движение
отключено. Сообщения отображаются как текст, максимум 500 символов; сервер разрешает
одно сообщение раз в 750 мс. Поле очищается после подтверждения отправки; при ошибке
текст сохраняется. Панель чата сворачивается, а новые сообщения отмечаются счётчиком.

В каждой комнате хранятся последние 60 сообщений каждого канала. Это история
текущей встречи в памяти сервера: она исчезает после перезапуска или закрытия
пустой комнаты. Сохранение переписки проектов в базе относится к этапу Project Rooms.

## Публикация на Render

`render.yaml` описывает один Node-сервис: Next.js и Colyseus обслуживаются на одном
порту и одном домене. `npm run serve` запускает общую production-версию после сборки.
Адрес сервера Café автоматически совпадает с адресом сайта, если
`NEXT_PUBLIC_WORLD_URL` не задан. При публикации не задавайте эту переменную адресом localhost.

Для создания сервиса подключите аккаунт Render и репозиторий GalaxyHub.
Команда сборки: `npm ci --include=dev && npm run build`. Команда запуска: `npm run serve`.
Проверка готовности: `/health`. Бесплатный тариф может засыпать без запросов;
для постоянной работы нужен соответствующий тариф. В памяти одного сервиса
хранятся текущие комнаты; перезапуск завершает подключения. Несколько экземпляров
потребуют отдельной общей инфраструктуры Colyseus и здесь не настроены.

В Render задайте публичные настройки Supabase до сборки. В Supabase добавьте
в Redirect URLs callback-адреса опубликованного сайта. Гостевой Café не зависит
от базы PostgreSQL или Supabase. `/api/health` дополнительно проверяет локальную
PostgreSQL; для hosted Café используйте `/health`.

На Render при `NODE_ENV=production` зависимости сборки устанавливаются явно через
`npm ci --include=dev`. TypeScript нужен для сборки, а `tsx` — для запуска общего сервера.
Файл `.npmrc` также включает зависимости сборки, чтобы уже созданный Render-сервис
со старой командой `npm ci && npm run build` смог собраться после обновления кода.
